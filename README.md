# 畅飞卡全国航线地图

根据参考航线图片表格整理的全国航线交互地图。使用原生 HTML、CSS、JavaScript 和 SVG，地图、参考航线和官网航班查询快照内嵌在一个 HTML 文件中，可离线打开，无需安装依赖、申请地图 API Key 或启动后端。

![杭州可往返目的地预览](docs/preview.jpg)

## 使用

下载仓库后，用现代浏览器直接打开 [`index.html`](index.html) 即可。

也可以在本地启动静态服务器：

```bash
git clone https://github.com/buyfakett/clsxf-2026.git
cd clsxf-2026
python3 -m http.server 8000 --bind 127.0.0.1
```

然后访问 <http://127.0.0.1:8000>。页面可以部署到支持静态 HTML 的托管服务。

## 功能

- **全国地图与航线**：显示城市节点与目的地连线，点击城市查看它的出发航线。
- **搜索城市或机场**：支持中文名称的包含匹配；点击候选项，或按 Enter 选择首个匹配结果。当前不支持拼音和机场三字码。
- **放大、缩小与平移**：支持 `+` / `−` 按钮、鼠标滚轮、双指缩放及拖动平移，缩放范围为 100%–600%；点击“复位”恢复全国视角。
- **往返筛选**：点击“只看可往返”，只显示双向都有记录的城市对；绿色连线与“可往返”标记表示存在双向记录。
- **目的地列表**：点击列表中的目的地可继续查看该城市的航线。
- **官网航班快照**：在侧栏选择出发日期，展开目的地下的“官网航班”，查看已保存的航班号、计划时刻、机场、查询日期及来源链接；往返模式分别显示去程和返程。切换日期保留已展开的详情，未保存的日期会提示尚未查询，并提供官网查询入口。
- **恢复总览**：点击“显示全部航线”清除城市选择和往返筛选。选择城市和切换筛选时保留当前地图视角。
- **适配窄屏**：窄屏下地图与目的地列表按上下顺序显示。

## 往返判定与数据说明

只有当前整理数据同时收录 `A → B` 和 `B → A` 时，才标记为“可往返”。往返总览将两个方向合并为一个城市对，避免重复计数。

“返程未收录”只说明当前数据中没有对应的反向记录，不代表航空公司实际没有返程航班。

当前页面包含：

| 数据 | 数量 |
| --- | ---: |
| 城市 / 机场节点 | 72 |
| 有向航线记录 | 402 |
| 双向都有记录的城市对 | 200 |

航线按原图表格横线逐行抄录，并已完成两次独立读图核对。公开参考数据及原图疑点见 [`data/reference-routes.json`](data/reference-routes.json)。城市坐标为示意位置。参考连线与官网日期查询快照分别记录，官网某日查询结果不会自动修改地图的参考航线或往返判定。实际可飞航线与活动规则以航司预约页面为准。

表头的 **2026 年 11 月 13 日—11 月 22 日** 是部分往返航班不可适用的例外提示，不能当作整张参考航线表的有效期。低清原图中日期后的文字及部分城市不够清楚，具体限制范围以实际预约规则为准。

原图保留了两条不对称记录：`哈尔滨 → 常州`、`深圳 → 哈尔滨`。其中哈尔滨行“常州”一项存在原图文字、排印或低清辨识疑点；数据按读图结果保留，不把它自动改成深圳，也不为对称而补返程。这两条不计入 200 组双向城市对。

地图边界数据来源：[阿里云 DataV 全国省级 GeoJSON](https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json)，已精简并内嵌到页面中。

## 官网航班快照

当前内嵌 **2026-11-02 的 49 个方向、64 条已核实航班记录**。其余 353 个方向尚未取得确认明细，提供按机场和日期打开官网的查询入口；这不是覆盖全部参考航线的完整时刻表。72 个机场代码均已从官网选择器核实。原始空页面可能仍在加载，因此本次没有将未确认的空结果发布为“无航班”。

官网航班区域展示的是**某个日期、某次查询时保存的结果**，不是实时班期、在售情况或畅飞卡可预约余票。 **官网查到航班不代表该航班可用畅飞卡兑换**，是否可兑换仍以畅飞卡预约页面为准。出发日期默认使用已保存快照的日期；修改日期只切换本地快照，没有该日期的记录时会提示“尚未保存”，并提供长龙航空官网查询入口。

- 航班号、机场及计划起飞 / 到达时刻仅按该日期的官网结果展示，时刻采用北京时间。
- 仅在实际采集到 `flightStatus` 时显示航班状态：取消采用醒目标记，延误采用暖色标记；未采集到状态时不推断为正常、取消或延误。状态同样只是查询时的快照。
- 只在官网明确提供次日信息时标记 `+1`；未提供的信息不会通过时钟大小推测，也不会用单日结果推断每周班期。
- 去程和返程分别显示、分别查询；“尚未保存”“查询未完成”“机场待核实”都不代表没有航班。
- 官网结果可能延迟加载，暂时空白或未看到结果不等于没有航班。未确认的空结果按查询未完成、待核实处理，不据此断言该日无航班或已经停飞。
- 每个方向保留来源链接及查询时间，可前往官网再次核实。机场代码未核实时，链接会打开官网入口，由用户选择机场。

## 项目结构

```text
.
├── index.html               # 页面入口，内含样式、地图、航线数据和交互代码
├── README.md                # 使用说明
├── data/
│   └── reference-routes.json # 原图参考航线、日期例外与待核实疑点
├── data/
│   ├── reference-routes.json # 逐行复核的原图航线与文字疑点
│   └── official-flights.json # 官网日期快照、来源及查询覆盖范围
├── docs/
│   └── preview.jpg          # 页面预览
└── tests/
    ├── map-gestures.cjs     # 缩放与手势回归检查
    └── official-flights.cjs # 官网快照日期、方向、状态和链接检查
```

直接编辑 `index.html` 即可维护页面，无需构建。内嵌的 `data.cities` 保存名称与经纬度，`data.routes` 保存出发地及目的地列表；新增航线时应确保两端名称均有坐标，往返状态会根据两个方向的记录自动计算。

`data/official-flights.json` 是可审阅的官网快照副本，页面仍内嵌相同数据，不需联网加载这个文件。修改快照时同步更新 `index.html` 中的 `officialFlightData`。

`officialFlightData` 单独保存官网快照：`date` 为默认出发日期，`retrievedAt` 为整理时间，`airportCodes` 映射已核实的机场代码，`queries` 按出发地、目的地、日期保存查询状态、航班列表、官网来源和查询时间。每条航班的 `flightDate` 必须与所选日期一致才会显示；快照数据可以更新，页面交互无需构建。

## 验证

如已安装 Node.js，可运行以下检查；检查使用 Node.js 内置模块，无需 `npm install`：

```bash
node tests/map-gestures.cjs
node tests/official-flights.cjs
```

检查覆盖拖动时的指针捕获、多指缩放后误点击抑制、1–6 倍缩放边界，以及取消手势后的状态清理。页面还经过浏览器中的搜索、往返筛选、按钮缩放、滚轮缩放、拖动和复位检查。

官网快照检查直接从 `index.html` 提取实际页面中的辅助代码，使用独立测试数据验证精确日期、去返程独立、未知与无结果状态、官网链接安全、日期切换保留城市选择和已展开详情，以及未提供跨日信息时不推测次日到达；不要求实际快照包含固定数量的航班。
